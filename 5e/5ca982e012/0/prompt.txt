## Summary

**Verdict:** Do not build a Google Contacts bulk-import feature for the MVP -- but for a different reason than LinkedIn. Google's People API self-serve OAuth scope (`contacts.readonly`) is genuinely buildable with no partner approval, unlike LinkedIn's Connections API. The blocker is Euno's own product scope (PRODUCT.md / MVP doc rule out bulk import; a flat contact list has no "how you met" story), not a technical or legal gate from Google.

**Options evaluated:**

1. **Google People API OAuth (`contacts.readonly`)** -- self-serve, no partner gate. Classified as a *sensitive* scope (not *restricted*), so it needs standard app verification (brand + data-access review, roughly days to a few weeks per Google, though real-world reports describe longer) but **not** the annual CASA security assessment reserved for restricted scopes like full Gmail/Drive. Clerk requires switching to custom Google OAuth credentials to request this extra scope. Feasible; weak product fit; recommend not building now, but flagged as the front-runner if bulk import is ever reopened.
2. **Native Android `ContactsContract`** -- not reachable from a web app at all; not applicable to Euno's stack.
3. **W3C Contact Picker API** (`navigator.contacts.select`) -- Chrome/Android only (Chrome 80+, Android M+), not Baseline, no iOS Safari/Firefox/desktop support. Feasible only as a narrow single-browser convenience; recommend skipping given inconsistent reach.
4. **vCard/CSV export from Google Contacts / Google Takeout** -- fully legal, zero infrastructure, same flat-list/no-context problem as the API path. Recommended as a fallback only if bulk seeding is ever reopened.

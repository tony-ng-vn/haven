## Findings, most severe first

**1. HIGH - The probe can show a false green in exactly the failure mode Phase 0 exists to catch.**
`ios/Haven/ProfileProbe.swift:28` - `.replaceError(with: nil)` swallows every `ClientError` from the subscription and renders it as `profile = nil`, `loaded = true`, which the UI displays as "Signed in. No profile row yet." (ProfileProbe.swift:50). I verified in convex-swift that server errors arrive on the subscription's failure channel (`SubscriptionAdapter.onError` sends `ClientError.ServerError`/`ConvexError`, ConvexMobile.swift:366-374 in the checkout). The dangerous scenario: Clerk mints a token (so `authState` flips to `.authenticated` - the client sets that purely on token fetch success, ConvexMobile.swift login()), but Convex rejects it (wrong `CLERK_JWT_ISSUER_DOMAIN`, misconfigured "convex" JWT template). Then `requireUser` throws "Not signed in" (convex/profiles.ts:83), the subscription errors, and the probe shows the success-looking nil branch. The comment at ProfileProbe.swift:15-17 ("an unauthenticated call would throw ... instead of returning a value") is true of the server but the client masks precisely that throw. README.md:48 then overclaims: "Seeing 'Signed in' (with or without a profile row) means the authenticated Convex call succeeded end to end" - only the `@username` outcome is unambiguous proof.
Fix: model three outcomes instead of bool+optional - e.g. `enum ProbeState { case loading, value(MyProfile?), failed(String) }`, use `.map { ProbeState.value($0) }.catch { Just(.failed(String(describing: $0))) }`, and render the error text in a `.failed` branch. Update README.md:48 to match. This is a small change and it converts the probe from "can lie" to "cannot lie".

**2. MEDIUM - First error permanently kills the live subscription, silently.**
Same line, ProfileProbe.swift:28: `replaceError` completes the pipeline after replacing the error, so any transient failure ends the stream with no retry and no indication. The Phase 0 DoD is explicitly "see a live update pushed to the screen" (mvp-design.md:270); a stream that dies after one error silently stops demonstrating liveness. The finding-1 fix makes the death visible, which is enough for Phase 0; retry logic can wait. Related README gap: the Run section (README.md:44-48) never tells the human to exercise the live-update half of the DoD. Suggest one line: after signing in, change the username on the web app and watch the phone update untouched - that both proves liveness and disambiguates the probe.

**3. LOW - Dead operator plus misleading comment in AuthModel.**
`ios/Haven/AuthModel.swift:14` - `.replaceError(with: .unauthenticated)` is a no-op: I verified `authState` is `AnyPublisher&lt;AuthState&lt;T&gt;, Never&gt;` backed by `CurrentValueSubject&lt;_, Never&gt;` (ConvexMobile.swift:240-245), so its failure type is `Never` and no error can ever occur. It compiles fine (and `assign(to:)`'s Failure == Never requirement is satisfied), but the comment at AuthModel.swift:5-7 ("A subscription error is treated as unauthenticated so the UI never gets stuck on the loading spinner") describes behavior that cannot happen. The operator is copied verbatim from the example's AuthModel (which has the same no-op); the comment is this repo's own addition and is wrong. Minimal fix: correct or delete the comment; optionally drop the operator too.

**4. LOW - Cold-start flash of the sign-in screen for returning users.**
The client's `authPublisher` starts at `.unauthenticated` (ConvexMobile.swift:240) and replays immediately on subscribe, so AuthModel's `.loading` default is overwritten with `.unauthenticated` before the provider's session sync runs `loginFromCache()` (which then emits `.loading` -&gt; `.authenticated`). A signed-in user will briefly see the "Haven / Sign in" screen on every launch. Identical to the example app's behavior; acceptable for Phase 0, but expect it when testing and fix in Phase 1.

**5. LOW - Device signing gap for the physical-iPhone DoD.**
`ios/project.yml` sets no `DEVELOPMENT_TEAM`, and the README's compile-check (README.md:52-56) disables signing. Fine for simulator, but the strict DoD is a physical iPhone, and a team set by hand in Xcode is wiped every `xcodegen generate`. Worth a README note (set the team in Signing &amp; Capabilities after each generate) or a `DEVELOPMENT_TEAM` base setting.

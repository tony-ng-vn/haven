## Contract ambiguities and how I resolved them

- **`oneToOneThread` edges**: confirmed by reading `GraphBuilder.swift` that these always have `"user"` on one end (a one-to-one chat is definitionally you plus one other person), so "ignore the user's edges" already fully covers them — no separate handling needed.
- **Live toggle vs. layout/regions**: checking/unchecking a chat in the groups drawer recomputes tiers, drawn lines, the side panel, and the top-N label set, but does **not** re-run the force layout or community/region assignment. The initial layout and regions are computed once at load using the *effective* set (shipped `fullyAcquaintedChatIds` plus any valid stored marks), so a pre-checked chat's promoted pairs are already reflected in the first settle. I judged re-laying-out on every checkbox click to be a bigger surprise than the toggle itself, and PLAN.md's "the map rests" framing supports this — but the brief doesn't say this explicitly, so flagging it as my call.
- **Score floor for marker-created pairs**: `CONFIRMED_MARKER_SCORE = 2`, above the "strong" cutoff (1.0), `Math.max`'d with any prior score. Needed so a brand-new confirmed pair is cheap (not `Infinity`) in shortest-path's `1/score` weighting. Pinned by a test.
- **"Copy marks as JSON" payload**: exports the *effective* checked-chat set (shipped defaults plus in-page marks), not only marks toggled in this browser session. I judged this the more self-consistent, round-trippable snapshot ("here is everyone this page currently treats as fully acquainted"), but it is a reading of the brief, not a literal instruction — flagging as an assumption per the advisor's request.
- **Region dominant-chat tie-break**: raw member-count overlap (not weighted by score), ties broken by smallest group id.
- **Search**: implemented as an always-visible, always-tab-reachable input rather than a keyboard-shortcut overlay (v3's Cmd-K pattern), since the brief calls search "a primary way in."

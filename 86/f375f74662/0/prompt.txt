## Codebase finding (before writing anything)

Facebook is already a first-class capture platform, with identical treatment to LinkedIn:
- `convex/openaiClient.ts` - `facebook` sits in the same `PLATFORMS` enum as `linkedin`.
- `src/lib.ts` - `deriveProfileUrl` returns `null` for Facebook; the existing code comment names Facebook explicitly alongside LinkedIn as a platform whose vanity-slug URL never appears in a screenshot.
- `src/CaptureTriage.tsx` - `facebook` has a `PLATFORM_LABELS` entry and falls into the same paste-a-link triage path.

No engineering gap exists for Facebook capture today.

## Verdict reached

**Do not build a Facebook data/API integration.** Keep Facebook as capture-only (already done). No real "optional later" beyond generic Facebook Login for auth.

## Options evaluated (mirrors the LinkedIn doc's structure)

1. **Friends import via Graph API** - `user_friends`/`/user/friends` still only returns friends who have *also* authorized the same app and haven't declined the permission (confirmed on Meta's current v25.0 docs, unchanged since 2018). This isn't a partner-approval gate like LinkedIn's - it's self-defeating: it only returns anything once most of a user's friends already use Euno. Recommend: skip.
2. **Enrich a person from a pasted Facebook URL** - no API exists for third parties to look up an arbitrary other person's profile; `public_profile` only returns id/name for the *authenticated* user. Scraping is ToS-prohibited (Meta Platform Terms bar automated data collection and third-party data transfer). Recommend: don't build, don't scrape.
3. **Facebook's "Download Your Information" export** - legal, self-service, no API needed, same shape as LinkedIn's CSV option. But weaker: the `friends_and_followers/friends.json` file contains only name + connection timestamp, no email, no company/position/context - even thinner than LinkedIn's connections export, and a worse fit against Euno's anti-social-graph, anti-bulk-import stance. Recommend: not now.
4. **Sign in with Facebook (Login)** - auth only, same rating as LinkedIn OIDC. Recommend: optional later.
5. **Post/share to Facebook** - out of scope for Euno's one job. Skip.
6. **Facebook-aware capture UX** - already implemented identically to LinkedIn; only follow-up is folding `facebook` into the existing LinkedIn link-paste-copy ticket when it ships.
